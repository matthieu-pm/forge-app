## How to use dependencies

Start with [FOR-25](<https://linear.app/atriumcrm/issue/FOR-25/identify-the-serving-production-services-and-database>) (serving-environment identity), [FOR-20](<https://linear.app/atriumcrm/issue/FOR-20/agree-the-production-release-scope-and-feature-gates>) (release contract) and [FOR-128](<https://linear.app/atriumcrm/issue/FOR-128/validate-and-safely-migrate-personal-preference-schemas>) (pure schemas/defaults). These have no native prerequisites. Work in different milestones can proceed concurrently once its interfaces and policy are clear.

**Blocked by** means a prerequisite for completing the issue's acceptance contract. It does not prohibit drafting, fixture tests or agreed-interface implementation. Transitive prerequisites remain enforced without repeating every ancestor as another direct link.

**Related to** can identify coordination or conditional work. When a surface is enabled, its implementation and acceptance evidence remain mandatory even when it is not an unconditional graph blocker. Every release must have a manifest mapping selected features to issue/gate evidence and owners. Missing evidence blocks that selected surface. An exclusion requires a recorded decision plus enforced UI/direct-route/job behavior; it never marks unfinished implementation Done.

The core go/no-go is [FOR-123](<https://linear.app/atriumcrm/issue/FOR-123/approve-and-execute-the-controlled-core-production-launch>). [FOR-103](<https://linear.app/atriumcrm/issue/FOR-103/disable-unfinished-features-consistently-across-ui-and-server-routes>) prevents hidden routes, tools, previews or background execution bypassing the manifest. [FOR-124](<https://linear.app/atriumcrm/issue/FOR-124/verify-production-behavior-and-resolve-launch-regressions>) checks the actual serving release.
