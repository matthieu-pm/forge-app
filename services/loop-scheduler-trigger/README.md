# Forge Loop scheduler trigger

The Cloudflare minute trigger sends one authenticated POST to Forge's fixed production web scheduler. Forge retains queue ownership, the four-minute execution deadline, model/spend/tool permissions and durable run history. The Worker does not connect to the database or receive model credentials. Its public fetch handler is inert, and workers.dev/preview URLs are disabled.

`CRON_SECRET` is a private Worker secret binding with the same value as the Vercel production scheduler secret. Never put its value in source, Wrangler config, logs or build artifacts. `worker-configuration.d.ts` is generated by Wrangler; local `.dev.vars` files are ignored.

```sh
bun run test
bun run typecheck
bun run build
bun run types
```

For deployment, upload `dist/index.js` as an ES module with the compatibility date/flags and observability settings from `wrangler.jsonc`. Bind the secret and keep schedules empty until the reviewed Forge web deployment is live and verified. Then configure `* * * * *` and verify the saved schedule plus successful invocation receipts. The connected account and script name are pinned in Wrangler configuration. Redeployment must preserve existing secret bindings.

Set `FORGE_LOOP_SCHEDULER_DRIVER=cloudflare` for the production web build: the 300-second scheduler function remains, but no native Vercel Loop Cron is emitted. Vercel Hobby therefore does not need a plan upgrade. The Worker awaits the request with a 290-second network deadline, consumes at most 4 KiB of receipt data, logs only counters/status and never retries an ambiguous request. The next minute is a new queue tick; Forge's durable claims prevent replay.

Cloudflare documents [scheduled invocation limits](https://developers.cloudflare.com/workers/platform/limits/) separately from CPU time, and [Cron changes can take up to 15 minutes to propagate](https://developers.cloudflare.com/workers/configuration/cron-triggers/). Inspect scheduled invocation logs before declaring release qualification. To stop ticks, remove the Worker's schedule; disabling the Forge product gate also denies execution and callbacks. Keep the database expansion during application rollback.
